# API Baseline

Verified against the generated Minecraft/NeoForge sources for Minecraft 26.1.2 and NeoForge 26.1.2.114, plus the SISE-Core `26.1.2` reference branch. Version-sensitive integrations belong in `core/compat/`; registry declarations remain in `core/registry/`.

| Check | Proposal assumption | 26.1.2 source fact | Adopted form |
| --- | --- | --- | --- |
| Identifier type | `Identifier` or `ResourceLocation` needs confirmation. | `net.minecraft.resources.Identifier` is the active class; the reference uses it throughout. | Use `Identifier`, created with `Identifier.fromNamespaceAndPath(MOD_ID, path)`. |
| Attributes | Attributes may be datapack registries. | `BuiltInRegistries.ATTRIBUTE` bootstraps through `Attributes::bootstrap`; `Registries.ATTRIBUTE` is absent from `RegistryDataLoader`'s datapack registry lists. | Register custom attributes with `DeferredRegister<Attribute>` against `Registries.ATTRIBUTE`; do not author attribute datapack entries. |
| Data Attachments | NeoForge attachment API shape is version-sensitive. | `AttachmentType<T>` is stored in `NeoForgeRegistries.Keys.ATTACHMENT_TYPES`; its builder supports serialization and explicit sync. `IAttachmentHolder` exposes typed attachment access. | Use `DeferredRegister.create(NeoForgeRegistries.Keys.ATTACHMENT_TYPES, MOD_ID)` and `AttachmentType.builder(...).serialize(...).build()`; use `sync(...)` only when the attachment needs client copies. |
| Custom payloads | Register through `RegisterPayloadHandlersEvent`. | The event is a mod-bus event; `registrar(version)` returns the `PayloadRegistrar` used for `playToServer` / `playToClient`. | Add a mod-bus listener for `RegisterPayloadHandlersEvent`; keep payload definitions and registration in `core/compat/`. |
| Data Components | Register and read custom item components. | `Registries.DATA_COMPONENT_TYPE` is a built-in registry. NeoForge provides `DeferredRegister.createDataComponents(...)` and `registerComponentType(...)`; types use `DataComponentType.builder()` with `persistent(codec)` and optional `networkSynchronized(codec)`. | Register with `DeferredRegister.DataComponents`; read and write through `ItemStack.get`, `getOrDefault`, `set`, and `remove`. |
| Data generation | Provider class names and constructors may differ from older tutorials. | NeoForge exposes concrete `GatherDataEvent.Client` and `.Server` subclasses, `getGenerator()`, `createProvider(...)`, and `LanguageProvider(PackOutput, modId, locale)`. The current sources do not provide the older `BlockStateProvider` / `ItemModelProvider` helper classes. ModDevGradle's run type is `clientData` (task `runClientData`), not the older `data` type. | Listen for `GatherDataEvent.Client`; use `LanguageProvider` for translations and small project-owned `DataProvider` implementations for blockstates, item models, tags, and recipes. Use `PackOutput.Target` paths and `DataProvider.saveStable(...)`. |
| MobEffect and sync | Effects are visual mirrors, not authoritative status storage. | `MobEffect` is a registry entry constructed through a subclass; active effect instances use the vanilla entity effect synchronization path. | Register mirror effects in `Registries.MOB_EFFECT`; keep custom status state separate and do not add a second sync channel for the mirrors. |
| GameTest | Confirm annotation and launch conventions. | The 26.1.2 source uses test-instance and environment registries. NeoForge fires `RegisterGameTestsEvent` on the mod bus; the reference registers `GameTestInstance` values there. No annotation-based test entry point appears in the target source set. | Register a `GameTestInstance` from `RegisterGameTestsEvent`; run via ModDevGradle's `runGameTestServer` task. |

## Source Anchors

- Minecraft source jar generated by the pinned ModDevGradle build: `Identifier`, `Registries`, `BuiltInRegistries`, `RegistryDataLoader`, `DataComponentType`, `DataComponents`, `MobEffect`, `PackMetadataSection`, and `PackFormat`.
- NeoForge 26.1.2.114 sources: `AttachmentType`, `IAttachmentHolder`, `DeferredRegister`, `NeoForgeRegistries`, `GatherDataEvent`, `LanguageProvider`, `RegisterPayloadHandlersEvent`, and `RegisterGameTestsEvent`.
- SISE-Core `26.1.2`: `SiseCore.java` demonstrates `Identifier` and deferred registration; `BlueprintNetwork.java` demonstrates payload registration; `CoreGameTests.java` demonstrates GameTest registration and `runGameTestServer` is documented in its contribution guide.

## Additional 26.1.2 Runtime Notes

- `GatherDataEvent` is abstract and cannot be subscribed to directly; the current client DataGen run dispatches `GatherDataEvent.Client`.
- `pack.mcmeta` uses `min_format` / `max_format` for the 26.1 pack metadata schema. The resource and data pack format versions are 84.0 and 101.1, respectively; the project range covers both.
- ModDevGradle exposes `clientData` and `serverData` run types. The configured `runClientData` task executes all M0 providers.
- The Java 25 mod toolchain is unchanged. ModDevGradle's asset download task also requests Java 21; systems with both runtimes should expose the Java 21 installation to Gradle toolchain discovery.
